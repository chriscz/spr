# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`git spr` is a Go CLI that manages stacked pull requests on GitHub. Each commit on a single branch becomes its own pull request, kept in sync and ordered. This is a fork of `ejoffe/spr` (note: `readme.md` is the fork's rewritten docs; upstream module path `github.com/ejoffe/spr` is retained).

## Commands

```shell
go build ./...                  # build everything
go test ./...                   # run all tests
go test -race ./...             # tests with race detector (matches CI)
go test ./spr/ -run TestName    # run a single test
make bin                        # snapshot binary via goreleaser -> dist/ (needs goreleaser)
go generate ./...               # regenerate the fezzik GraphQL client (see below)
```

CI runs `go build -v ./...`, `go test -race -coverprofile=... ./...`, and `goreleaser check`.

## Dev environment

`nix develop` drops you into a shell with the full toolchain (`go`, `goreleaser`, `git`) pinned by `flake.nix`. The same flake is also the Nix distribution target — `packages.spr` is what `nix profile install github:ejoffe/spr` / `nix run` build, so the flake is load-bearing for releases, not just local dev.

## Architecture

Flow: `cmd/spr/main.go` (CLI wiring with `urfave/cli`) → `spr.stackediff` (orchestration in `spr/spr.go`) → two injected interfaces it drives:

- **`git.GitInterface`** (`git/`) — shells out to git. Real impl in `git/realgit/`, mock in `git/mockgit/`.
- **`github.GitHubInterface`** (`github/`) — talks to GitHub's GraphQL API. Real impl in `github/githubclient/`, mock in `github/mockclient/`.

`stackediff` is constructed via `spr.NewStackedPR(cfg, client, gitcmd)` and holds all command logic (`UpdatePullRequests`, `MergePullRequests`, `StatusPullRequests`, `AmendCommit`, `EditCommit*`, `SyncStack`, `RunMergeCheck`). Tests use the mocks to script exact git command / API call sequences, so changing the order or text of git invocations in real code usually requires updating the corresponding mock expectations.

### Key mechanisms

- **Commit IDs**: each commit gets a stable `commit-id` appended to its message body on first `update`. It survives amends (unlike the git hash) and is how a local commit is matched to its PR. Stack parsing lives in `git/helpers.go` (`GetLocalCommitStack`, `parseLocalCommitStack`).
- **Branch names**: PR branches are derived from the commit ID + `branchPrefix` config via `git.BranchNameFromCommit` / `BranchNameRegex`.
- **`spr edit`** uses an internal `_edit-sequence` subcommand: the binary re-invokes itself as git's sequence editor to rewrite `pick` → `edit` in the rebase todo. Handled at the very top of `main()` before any config/git init.
- **Status bits**: the `[✅❌✅✅]` display = checks / approval / conflicts / stack-readiness; rendering in `github/pullrequest.go`, requirements driven by `requireChecks`/`requiredChecks`/`requireApproval` config.

### Configuration

Config is layered via the `rake` library across three structs in `config/config.go`: `RepoConfig` (`.spr.yml` at repo root), `UserConfig` (`~/.spr.yml`), and `InternalState`. Defaults come from `default:` struct tags. Parsing/auto-detection of GitHub owner/remote is in `config/config_parser/`. The README's two config tables are the authoritative list of settings.

## Code generation

The GraphQL client under `github/githubclient/gen/genclient/` is generated by [fezzik](https://github.com/inigolabs/fezzik) — **do not edit by hand** (files marked `DO NOT EDIT`). Source of truth:

- `github/githubclient/queries.graphql` — the queries/mutations
- `github/githubclient/github.schema.graphql` — GitHub's schema
- `github/githubclient/fezzik.yaml` — generator config

Regenerate with `go generate ./...` (directive in `github/githubclient/client.go`). Hand-maintained types that fezzik can't express live in `github/githubclient/fezzik_types/`. The mock client in `github/mockclient/` is hand-written, not generated.

## Conventions

- The repo manages its own PRs with `git spr` (`master` is the target branch per `.spr.yml`). Avoid `git add -A` in spr's own logic — it was a past bug; stage explicitly.
- `terminal/` and `git/realgit/` have platform-split files (`*_windows.go` / `*_other.go`, `maybeAdjustPathPerPlatform`); keep both in sync when touching platform behavior.
